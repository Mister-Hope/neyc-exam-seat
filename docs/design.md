## 1. 目标与范围

### 1.1 一句话方案

核心算法是一个**零依赖 JS 包**，网页和命令行都只是它的壳，两者用同一份 `job.json` 作为契约。

- 老师走**网页**：导入名单 → 点选配置 → 看结果 → 导出名单。
- AI 走 **CLI**：把自然语言 / Excel 变成 `job.json` → 调包 → 读结构化诊断 → 转述或修复重跑。
- 排不出来时不甩一句「失败」，而是给出**为什么 + 怎么放宽**的机器可读建议；要退让时**明确标注降级**，绝不静默。

### 1.2 需求确认

| #   | 需求         | 说明                                                                                         |
| --- | ------------ | -------------------------------------------------------------------------------------------- |
| 1   | Web 应用     | 导入 `.xlsx`，查询排除缺考，可视化配置，导出名单                                             |
| 2   | 核心包       | 算法封装为独立 JS 包，浏览器 / Node 通用，零运行时依赖                                       |
| 3   | CLI          | agent 可通过命令行或 import 调用，传选项拿明确结果                                           |
| 4   | Skill        | 项目级 skill，说明这个包能做什么、每个接口什么含义                                           |
| 5   | AI 填参      | 用户口述需求 → AI 理解 → AI 填写参数 → 调包 → 返回结果                                       |
| 6   | 限定规则     | **考场限定（单选）** + **行** + **列** + v2 的**班级 / 组合 / 科目选择器**                   |
| 7   | 考场配置     | 手动设总数；每个考场「大（6×7=42）/ 小（5×7=35）/ 自定义 行×列」，含地点、专用科目与专属组合 |

## 2. 交付形态与分层

### 2.1 目录结构

```
exam-seat/                          仓库根 = 项目根
├── packages/
│   ├── core/       @exam-seat/core    纯算法，零依赖，浏览器/Node 通用（ESM + CJS + IIFE）
│   ├── io/         @exam-seat/io      Excel 读写（SheetJS），浏览器/Node 通用；Node 专属封装在 ./node
│   ├── cli/        @exam-seat/cli     命令行，bin: exam-seat
│   └── web/        @exam-seat/web     Vue 3 单页应用（Vite）
├── .agents/skills/exam-seating/       ★ AI 用的项目级 skill（随项目打开生效）
│   ├── SKILL.md                       精简入口（渲染后必须 < 8192 字符）
│   ├── reference.md                   完整字段表 + 诊断码表
│   └── examples/job.sample.json
├── examples/                          示例名单、一键验收与冒烟脚本（pnpm acceptance / pnpm smoke）
├── scripts/                           仓库脚本（verifyCommit 等）
└── docs/
    └── design.md                      本文：**唯一的设计说明**（含待办与实现状态）
```

### 2.2 分层原则

`core` 不认识文件、不认识网络、不认识 DOM，只认内存里的对象。Excel 读写归 `io`，终端交互归 `cli`，
界面归 `web`。所以同一份算法能在浏览器和 Node 里跑出**逐字节相同**的结果（同 seed 同输入）。

| 层   | 允许依赖                | 禁止                                 |
| ---- | ----------------------- | ------------------------------------ |
| core | 无（零运行时依赖）      | `node:*`、DOM、任何第三方运行时依赖  |
| io   | `@exam-seat/core`、xlsx | DOM（`./node` 子路径才碰 `node:fs`） |
| cli  | core、io、commander     | 业务规则（只做参数解析、调用、渲染） |
| web  | core、io、Vue 生态      | 自己重写算法语义（一律调 core）      |

### 2.3 唯一契约

`job.json` 是 core / CLI / Web / AI 四者之间**唯一**的交换格式。老师可以在网页里配好再导出交给 AI；
AI 也可以生成 job.json 让老师在网页里打开复核、微调。任何一端都不能私自扩展字段含义：
**新增字段必须在本文档登记**，`core` 是语义的唯一解释者。

### 3.1 输入 `job.json`

  "options": {
    "seed": 20260930, // 固定种子 → 结果可复现
    "adjacency": "king", // king = 8 邻域（默认）；orthogonal = 前后左右
    "forceKing": false, // 班级数 < 9 时默认自动退化；置 true 则坚持 8 邻域
    "relax": "none", // none | softConstraints | minConflicts

### 3.2 字段语义

**最容易搞错的三个地方**（skill 里要重点写）：

| 字段                             | 语义                                                                                                                                                      |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `rows`                           | `"first"` 首排 ｜ `"last"` 末排 ｜ 数字 = 绝对排号（从**讲台**起算，**仅在指定考场时可用**）                                                              |
| `cols`                           | `"door"` 靠门列（小号列）｜ `"window"` 靠窗列（大号列，= 该考场最后一列）｜ 数字 = 绝对列号（从**靠门侧**起算，**仅在指定考场时可用**）                   |
| `roomId`                         | **单选**，不填 = 不限考场                                                                                                                                 |
| 四个选择器                       | `studentIds` / `classes` / `combinations` / `subjects` 取**并集**；至少写一个                                                                             |
| 同校多规则                       | 同一学生被多条规则命中时**取交集**，为空则报错                                                                                                            |
| `combination` / `subjects`       | v2 选科：原文 + 规范化科目 id；名单里有选科即进入多场次模式                                                                                               |
| `location` / `dedicatedSubjects` | v2 考场：地点（出现在监考表与座位表表头）与专用科目标记                                                                                                   |
| `combination`                    | 专属组合考场：只接收该组合的整批学生（整批进、全程不换考场）；与「限定钉考场」等价，连座位号一致（§5.5.1）                                                |
| `included: false`                | 本次不参加考试，容量校验按「实际参考」算                                                                                                                  |
| `groupPreference`                | 分房倾向：`"sameCombination"`（默认，一个考场只放同一组合）/ `"fillRooms"`（先填满当前考场）；两者都必须满足 §5.1 的硬规则                                |
| `relaxSameClass`                 | 考场级放宽（§5.8.1）：`true` 本考场同班相邻不算冲突、人数上限 = 座位数；数字 n = 本考场同班上限 n；**只影响本考场**，留 `ROOM_SAME_CLASS_RELAXED` warning |
| `extraFrontSeats`                | 加座（§4.5）：讲台一侧的**业务列号**数组，每列多 1 座；`roomCapacity = rows × cols + 长度`；加座行号为 `0`，不能被行 / 列限定点名                         |
| `subjectRoom`                    | 借考（§5.8.2）：`{ 科目 id: 考场 id }`，该科到指定考场考，其余科目留在主考场；**不产生第二张卷子**                                                        |
| `options.slots`                  | 显式时段表（§5.8.3）：`[{ id?, name?, subjects: [...] }, …]`，给了就**不再自动推导**；时段 id / name 缺省按顺序补齐                                       |

### 3.5 从 Excel 到 job.json：名单输入契约

工具只认「列的内容」，不认「列在第几列」。解析时表头与取值都做宽容处理：

**必填列（三列，缺一列就要明确报错，不能猜）**

| 列       | 含义                 | 可接受的表头写法（归一化后匹配，先全等再包含）                                                           |
| -------- | -------------------- | -------------------------------------------------------------------------------------------------------- |
| 准考证号 | 学生唯一标识         | `准考证号` `考证号` `准考证` `考号` `考生号` `学号` `学籍号` `考籍号` `编号` `id` `studentNo` `examNo` … |
| 姓名     | 学生姓名             | `姓名` `学生姓名` `考生姓名` `名字` `name`                                                               |
| 班级     | 行政班，相邻约束基础 | `班级` `行政班` `所在班级` `教学班` `班` `class` `grade`                                                 |
| 缺考     | _可选_，见下         | `缺考` `是否缺考` `缺考标记` `缺考状态` `不参加` `不参加考试` `缺席` `absent` …                          |

**表头归一化**：先去掉**所有空白**（含全角空格、Tab）、全角转半角、去掉 `_ - （）() ： :` 等分隔符、再转小写。
所以 `准 考 证 号`、`姓 名`、`班　级`（全角空格）都能认出来；包含匹配要求别名长度 ≥ 2，
**`班主任` 不会被当成班级列**。同一列只会归给一个字段（优先 id → 姓名 → 班级 → 缺考 → 选科 → 性别 → 备注）。

**缺考的两条路线（都要支持）**

| 路线                        | 输入                                                         | 规则                                                                                                                                                        |
| --------------------------- | ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A：名单里带「缺考」列**   | 一份**完整名单**，其中一列标记缺考                           | 该列**有内容即缺席**；但 `否 / 0 / N / no / false / 正常 / 参加 / 无 / -` 这类**否定值不算缺席**（兼容「是否缺考」列）。缺席者 `included: false`            |
| **B：另给一份缺考名单文件** | `exam-seat roster --file 全名单.xlsx --absent 缺考名单.xlsx` | 缺考名单**有准考证号列就优先按准考证号匹配**；没有准考证号列时，必须同时有 `姓名 + 班级` 两列。命中者 `included: false`，**未匹配的行必须报出来**（不静默） |

- 若「缺考名单」文件自己带「缺考」列 → 按**路线 A** 处理：它是一份完整名单，只取真正缺席的行。
- 匹配前对键做归一化（去空白、全角转半角、字母数字小写），避免「张 三」与「张三」、「高三 (1) 班」与「高三(1)班」匹配不上。
- 两条路线可以**同时用**，取并集。
- `included: false` 是唯一的「本次不参加」语义（§3.2）：容量校验、预检、导出全部按实际参考算。

> ⚠️ 识别「缺考」列时，表头含 `缺考 / 不参加 / 缺席` 的列都会被认出来（包括 `缺考情况说明` 这类）；
> 因此**只要认出缺考列，就一定要把「共 N 人标记为不参加」显示出来**（CLI 的 `stats.absent` / `--json` 的
> `absentCount`、网页的提示条），让老师能一眼发现「认错列了」并改用手动排除。不要静默按识别结果排除学生。

**网页对应行为**（§10.2）：导入名单后**自动预填**列映射并展示「自动识别：准考证号 → C 列」，认错可手改；
识别不到必填列时标红并提示手动指定；识别到「缺考」列时直接按路线 A 生效；
第 ② 步另有「导入缺考名单」按钮（路线 B），并保留「搜索 → 全量勾选 → 批量排除」的人工通道。

## 4. 座位编号、行列与限定

### 4.1 座位编号（方案 A）

```
1 号 = 右上角（靠门前角）
→ 沿本列向后到底 → 左移一列 → 从后往前 → 再左移一列 → 从前往后 → …
```

`seatNoToRC` 只按「列」蛇形推进，**返回的是业务列号**（从靠门侧起算，1 = 靠门列）：

```ts
// 真实签名：rows = 排数，cols 只为形状一致，编号本身不需要它
function seatNoToRC(seatNo: number, rows: number, cols: number): { row: number; col: number } {
  const k = Math.floor((seatNo - 1) / rows); // 第几列（从靠门侧数，0 基）
  const off = (seatNo - 1) % rows;
  const forward = k % 2 === 0; // 首列从前往后，次列从后往前
  const row = forward ? off + 1 : rows - off;
  return { row, col: k + 1 }; // 业务列
}

// 要在界面上按「面对讲台从左往右」的物理列画座位图时，再换算一次：
// doorSide === "right" → physicalCol = cols - col + 1
function toPhysicalCol(col: number, cols: number, doorSide: DoorSide = "right"): number;
```

**示例：5 列 × 6 排 = 30 座**（⚠️ 这是**编号规则示意**，不是当前网页预设——网页「小考场」预设已改为 5 列×7 排 = 35 座，见 §5.5/§10.2）

```
            讲台 / 黑板
        c1   c2   c3   c4   c5 ←门
  r1    25   24   13   12    1
  r2    26   23   14   11    2
  r3    27   22   15   10    3
  r4    28   21   16    9    4
  r5    29   20   17    8    5
  r6    30   19   18    7    6
```

**大考场（6 列 × 7 排 = 42）**

```
            讲台 / 黑板
        c1   c2   c3   c4   c5   c6 ←门
  r1    42   29   28   15   14    1
  r2    41   30   27   16   13    2
  r3    40   31   26   17   12    3
  r4    39   32   25   18   11    4
  r5    38   33   24   19   10    5

  r7    36   35   22   21    8    7
```

> 两张图都是**物理列序**（c1 在最左、门在右），格子里的座位号与 `seatNoToRC` 的业务列是左右镜像关系；
> 网页的座位缩略图就是这么画的。core 单测逐座比对这两张图，验收脚本再核对一次。

### 4.2 为什么行列必须分「语义值」和「绝对号」

考场有大小之分（6 排与 7 排、5 列与 6 列，都可能有），**同一个数字在不同考场指向不同位置**：

| 限定               | 在 5×6 考场（示意）      | 在 6×7 考场（42 人）    |
| ------------------ | ------------------------ | ----------------------- |
| `rows: ["first"]`  | 第 1 排（5 个座）        | 第 1 排（6 个座）       |
| `rows: ["last"]`   | 第 6 排                  | 第 7 排                 |
| `rows: [3]`        | 第 3 排                  | 第 3 排                 |
| `cols: ["door"]`   | 第 1 列（靠门）          | 第 1 列（靠门）         |
| `cols: ["window"]` | 第 5 列                  | 第 6 列                 |
| `cols: [5]`        | 第 5 列（= 靠窗）        | 第 5 列（**不是**靠窗） |
| `cols: [6]`        | 该考场没有第 6 列 → 排除 | 第 6 列（= 靠窗）       |

由此定两条硬规则：

1. **不限定考场时，行 / 列只能用语义值** `first` / `last` / `door` / `window`。
   求解器按**每个候选考场自己的行列数**解析：「末排」在小考场是第 6 排、大考场是第 7 排；
   「靠窗列」在小考场是第 5 列、大考场是第 6 列。这才是老师真正想表达的意思。
2. **限定了考场时，才允许写绝对号**（`rows: [3]`、`cols: [2]`）。此时已知该考场是几行几列，
   绝对号含义确定，并且会校验越界。

> 这正好解释了为什么绝大多数限定都填「首 / 末」：只有首排、末排、靠门列、靠窗列这四个语义值
> 在大小考场混排时是稳定的。老师想指定「第 3 排第 2 列」时，心里通常已经有一个确定的考场了。

### 4.3 限定数据模型与编译规则

```ts
type RowRef = "first" | "last" | number;
type ColRef = "door" | "window" | number;

type ConstraintGroup = {
  id: string;
  note?: string;
  // v2 选择器：四者取并集，至少写一个（否则 CONSTRAINT_NO_SELECTOR）
  studentIds?: string[]; // 按学号点名
  classes?: string[]; // 按班级，例如 ['高三(3)班']
  combinations?: string[]; // 按选科组合，例如 ['物化政']（写法可任选，内部规范化）
  subjects?: string[]; // 按所选科目，例如 ['politics']（命中选了其中任意一门的学生）
  roomId?: string; // 单选：undefined = 不限考场
  rows?: RowRef[];
  cols?: ColRef[];
};
```

编译规则：

```
命中学生(constraint) = studentIds ∪ classes ∪ combinations ∪ subjects      // 并集
allowedSeats(student) =
  对每个候选考场 R（roomId ? 就是它 : 全部考场）：
    行集合 = rows 里每个值按 R 解析出的行（rows 为空 → R 的全部行）
    列集合 = cols 里每个值按 R 解析出的列（cols 为空 → R 的全部列）
    R 的候选座位 = 行集合 × 列集合
  把所有候选考场的座位并起来
  ∩ 该学生命中的每一条规则        // 多规则取交集
```

| 语义值     | 解析                                                             |
| ---------- | ---------------------------------------------------------------- |
| `'first'`  | 第 1 排                                                          |
| `'last'`   | 第 R 排（R = 该考场的排数）                                      |
| `'door'`   | 第 1 列（靠门侧起算）                                            |
| `'window'` | 第 C 列（C = 该考场的列数）                                      |
| 数字 n     | 第 n 排 / 第 n 列；要求 n ≤ 该考场对应维度，否则**该考场被剔除** |

**越界处理**：绝对号在某考场越界 → 该考场从候选集剔除；所有候选考场都被剔除 → 报错
`CONSTRAINT_INDEX_OUT_OF_RANGE`。选择器解析结果为空 → `CONSTRAINT_NO_SELECTOR`。

### 4.4 UI 约束（不这么做老师一定会填错）

- **未选考场时，行 / 列下拉只列语义值**（首排 / 末排 / 靠门列 / 靠窗列），绝对号输入框直接隐藏；
- **选了考场之后**，才展开「第 N 排 / 第 N 列」，输入范围按该考场的行列数限制；
- 提供**四角一键预设**（自动填 `行=[首,末]`、`列=[靠门,靠窗]`，全是语义值，大小考场通吃）；
- 规则列表把语义值渲染成人话，悬浮提示写清它在各类考场的实际解析，例如：
  「靠窗列 → 5 列考场 = 第 5 列，6 列考场 = 第 6 列」。

典型用法：

| 场景                        | 配置                                                            |
| --------------------------- | --------------------------------------------------------------- |
| 只靠门，不在乎考场          | `cols: ["door"]`                                                |
| 强制到班主任监考的考场      | `roomId: "R3"`                                                  |
| 有作弊前科坐首排            | `rows: ["first"]`                                               |
| 4 人放同考场四角            | `roomId: "R5", rows: ["first","last"], cols: ["door","window"]` |
| 指定第 3 考场第 3 排第 2 列 | `roomId: "R3", rows: [3], cols: [2]`                            |
| 物化政全体靠门              | `combinations: ["物化政"], cols: ["door"]`                      |
| 考政治的考生靠窗            | `subjects: ["politics"], cols: ["window"]`                      |

### 4.5 非矩形考场：加座（5 列 × 7 排 + 讲台两侧 2 个加座 = 37 座）

> **状态：✅ 已实现**（`core/src/numbering.ts` 的 `columnSeatCounts` / `seatNoToRC` / `rcToSeatNo` / `seatNoToRCIn` /
> `maxSameClass`，`core/src/model.ts` 的 `extraSeat` / `extraCols`；测试 `core/test/nonrect.test.ts`；契约见 §5.8.4）。
> 真实教室的第 5 种规格：**5 列 × 7 排 = 35 座，再在讲台两侧（第 2、4 业务列）各加 1 张桌 = 37 座**，且"不能再多"。
> 不写清楚的话，排号一定会错。

#### 4.5.1 物理摆法

```
                讲台 / 黑板
        c1   c2   c3   c4   c5 ←门
 r0(加座)  ·   30    ·   15    ·     ← 讲台两侧加座：第 2 列、第 4 列各 1 张
  r1    31   29   16   14    1
  r2    32   28   17   13    2
  r3    33   27   18   12    3
  r4    34   26   19   11    4
  r5    35   25   20   10    5
  r6    36   24   21    9    6
  r7    37   23   22    8    7
```

- **最后一排（r7）是对齐的**：5 列都有第 7 排，不做参差。
- **加座在讲台一侧**（r1 之前，记为 r0），只加在第 2、4 列 —— 这两张桌子"突出来"。
- 图上按**物理列序**画（c1 最左、门在右），与 §4.1 的两张图同一画法；格子里的号与
  `seatNoToRC` 的**业务列**是左右镜像（业务第 1 列 = 靠门列 = 物理 c5）。
  **注意**：下文说的"第 2、4 列"是**业务列**，对应图上 **物理 c4 / c2**（5 列时两组互为镜像，加座集合恰好一样）。

#### 4.5.2 编号规则（这是最容易排错的地方）

编号仍然是 **按列蛇形**，唯一变化是**每列座位数不再相同**：

```
n_k   = 第 k 列（业务列，从靠门侧起算）的座位数 = rows + 该列的加座数
区间  = [ Σ_{i<k} n_i + 1 , Σ_{i≤k} n_i ]
列内顺序：k 为奇数 → 从前排往后排；k 为偶数 → 从后排往前排；
         加座（讲台一侧）永远排在该列**最后**一个号
```

本例 `n = [7, 8, 7, 8, 7]`，所以：

| 业务列          | 座位号    | 说明                                                     |
| --------------- | --------- | -------------------------------------------------------- |
| 第 1 列（靠门） | **1–7**   | 从前排到后排（靠墙那侧）                                 |
| 第 2 列         | **8–15**  | 8 = 最后一排，往前数到 14 = 第一排，**15 = 讲台侧加座**  |
| 第 3 列         | **16–22** | 第三列第一个人 = **16**                                  |
| 第 4 列         | **23–30** | 23 = 最后一排，往前数到 29 = 第一排，**30 = 讲台侧加座** |
| 第 5 列         | **31–37** | 从前排到后排                                             |

合计 7 + 8 + 7 + 8 + 7 = **37**。

> 老师原话逐句对账（防止理解错）：
> 「靠墙那边是 1~7」= 第 1 列 1–7；「甩过来，最后一个是 8」= 第 2 列**最后一排**是 8；
> 「往前数就不数到 14，而数到 15」= 第 2 列第 1 排是 14，**加座是 15**；
> 「第三排（列）的第一个人是 16」= 第 3 列从 16 开始。

#### 4.5.3 字段与实现要点（已落地）

```jsonc
// RoomSpec 新增
{
  "id": "R1",
  "name": "第一考场",
  "rows": 7,
  "cols": 5,
  "extraFrontSeats": [2, 4], // 第 2、4 业务列在讲台一侧各加 1 座；缺省 [] = 纯矩形
}
```

1. `roomCapacity(room) = rows * cols + extraFrontSeats.length`；本规格 = 37。
2. `seatNoToRC(seatNo, rows, cols, extraFrontSeats?)` / `rcToSeatNo(row, col, rows, cols, extraFrontSeats?)` 是**按列计数**的通用版，
   另有 `columnSeatCounts(rows, cols, extraFrontSeats?)` 与 `seatNoToRCIn(room, seatNo)`；`extraFrontSeats` 为空时结果与旧版**逐位相同**
   （§4.1 两张图与既有单测不变）。
3. `model.ts` 的 `CompiledRoom` 冻结 `extraSeat: Int32Array(cols)`（业务列 → 加座的全局座位下标，无加座为 `-1`）
   与 `extraCols: number[]`；`grid` 语义不变，只含第 1..rows 排，加座单独用 `extraSeat` 表达，`seatRow = 0`。
4. **邻接表**：加座与同列第 1 排、左右相邻列第 1 排相邻（8 邻域）；4 邻域只算同列第 1 排。加座之间不相邻（第 2、4 列中间隔着第 3 列）。
5. **同班上限 `maxSameClass` 按真实座位图的独立数算**，`4 邻域 = 二分图最大独立集、8 邻域 = 实际图最大独立集`。
   ⚠️ **订正**：设计文档早先写的「37 座 4 邻域 = `⌈37/2⌉` = 19」是错的 —— 因为加座都落在二分图的同一侧，
   两侧是 20 / 17，真正的最大独立集是 **20**。实测基准（`core/test/nonrect.test.ts`）：
   7×5 → king **12** / orth **18**；7×5 + `[2,4]`（37 座）→ king **12** / orth **20**；7×6 → king **12** / orth **21**。
6. 座位图缩略图（网页、座位表）画这一行"突出的加座"，不画成 7×5 的正矩形。
7. 越界校验：`rows:[8]`、`cols:[2]` 这类绝对号在本考场仍然越界（加座不算第 8 排，也不算第 0 排）；
   加座暂时不能被 `constraints` 精确点名（没有 `seatRef`），只由求解器自然填充 —— 已登记为遗留议题。

## 5. 选科与多场次排考

> 本章由原 `design-selection.md` 并入。适用前提：名单里带选科（`combination` 或 `subjects`）。
> 没有选科的名单就是普通单场排考，完全不受这一章影响。

### 5.1 总原则

> **常规组合（物化生、政史地）整个考试期间不换考场；只有非常规组合（物化政、物化地）中途换一次。**

#### 硬规则：一个考场，一个时段，只能考一科

**任何时刻，同一个考场里只能有一门科目在考**（只能发一张卷子）：某时段坐在这个考场里的学生，
必须全部在答同一门科目；没考试的学生就是不在这个考场，与规则无关。这条规则**不可降级、不可绕过**——
排不出来时宁可报容量不足，也不许把两门科目塞进同一个考场。

由此推出两条推论，实现时必须遵守：

| 推论                   | 说明                                                                                                                                                                                                                                                                                              |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **可以共用考场的前提** | 只有**逐时段不冲突**的批次才能共用一个考场：对每个时段，两批考生在这个时段要考的科目合起来**最多一门**（要么是同一门，要么只有一批有考试）。例：物化政 + 物化地共用一个「非常规主考场」（T1–T5 科目完全相同，T6/T7 各自去专用考场）；物化生 + 物化政也可以共用（T1–T5 同科，T6 只有物化生考生物） |
| **绝对不能共用的组合** | 常规理（物化生）× 常规文（政史地）：T4 一个考物理、一个考历史，T6 一个考生物、一个考政治，同一时段出现两门科目，必须分开考                                                                                                                                                                        |
| **共用就要合并座位**   | 能共用的批次在每个有考试的时段是**同时坐在这个考场里**的，所以必须合并成**一套座位方案**（学生并集、一次 `plan()`），否则两套座位会各自从 1 号开始排、座位号撞车                                                                                                                                  |

`planAll` 会逐「考场 × 时段」核对这条规则；一旦发现同一考场同时段出现两门科目，
立即报 `ROOM_SUBJECT_CLASH`（error），并且该结果不得导出。

这条原则把「多场次耦合优化」退化成**分组 + 分房间**：

- 每个**常规考场 = 一个组合 + 一套座位**，用到底；
- 每个**非常规主考场**同样一套座位用到底（考语数外物化）；
- 再加**政治专用考场**、**地理专用考场**各一套座位。

结果就是：**座位方案的数量 = 考场数量**，一个考场只需要排一次座位。
求解器完全不用改，只是被喂了不同批次的「考生 + 考场 + 限定」。

### 5.2 考场角色与「每人去几个考场」

| 考场角色         | 容纳谁          | 用在哪几个时段                                | 座位方案      |
| ---------------- | --------------- | --------------------------------------------- | ------------- |
| **常规理考场**   | 纯物化生        | T1 语 / T2 数 / T3 外 / T4 物 / T5 化 / T6 生 | 1 套，用 6 次 |
| **常规文考场**   | 纯政史地        | T1 语 / T2 数 / T3 外 / T4 历 / T6 政 / T7 地 | 1 套，用 6 次 |
| **非常规主考场** | 物化政 + 物化地 | T1 语 / T2 数 / T3 外 / T4 物 / T5 化         | 1 套，用 5 次 |
| **政治专用考场** | 只有物化政      | T6 政                                         | 1 套          |
| **地理专用考场** | 只有物化地      | T7 地                                         | 1 套          |

| 组合               | 主考场                | 换考场                 | 合计  |
| ------------------ | --------------------- | ---------------------- | :---: |
| 物化生（常规理）   | 常规理考场，考 6 科   | 无                     | **1** |
| 政史地（常规文）   | 常规文考场，考 6 科   | 无                     | **1** |
| 物化政（非常规理） | 非常规主考场，考 5 科 | T6 政治 → 政治专用考场 | **2** |
| 物化地（非常规理） | 非常规主考场，考 5 科 | T7 地理 → 地理专用考场 | **2** |

「最多三个考场」作为**硬上限校验**：任何学生超过 3 个考场就报警（正常情况下永远触不到，
`planAll().overRoomLimit` 应为空）。

> 默认假设物化政与物化地共用一个非常规主考场（考语数外物化时在一起）；要分开只是配置不同，模型不用改。

### 5.3 时段推导（从冲突关系推导，7 段）

学校只有 4 种组合，「哪些科目能同时考」是能精确推导的，不用人拍脑袋。
**两科能否同时考 = 有没有学生同时选了两科。**

| 组合对                    | 能否同时 | 理由                                              |
| ------------------------- | :------: | ------------------------------------------------- |
| 物理 × 历史               |    ✅    | 首选互斥                                          |
| 生物 × 政治               |    ✅    | 生物只有物化生选，政治是政史地 + 物化政选，无交集 |
| 生物 × 地理               |    ✅    | 同上                                              |
| 政治 × 地理               |    ❌    | 政史地两科都选                                    |
| 化学 × 生物 / 政治 / 地理 |    ❌    | 物化生 / 物化政 / 物化地 分别两科都选             |
| 化学 × 物理               |    ❌    | 三种理科组合都两科选                              |
| 语数外 × 任何             |    ❌    | 全体都考                                          |

推导结果：

| 时段 | 并行科目        | 物化生 | 政史地 | 物化政 | 物化地 |
| ---- | --------------- | ------ | ------ | ------ | ------ |
| T1   | 语文            | 语文   | 语文   | 语文   | 语文   |
| T2   | 数学            | 数学   | 数学   | 数学   | 数学   |
| T3   | 外语            | 外语   | 外语   | 外语   | 外语   |
| T4   | **物理 / 历史** | 物理   | 历史   | 物理   | 物理   |
| T5   | 化学            | 化学   | —      | 化学   | 化学   |
| T6   | **生物 / 政治** | 生物   | 政治   | 政治   | —      |
| T7   | 地理            | —      | 地理   | —      | 地理   |

「—」就是缺考。**化学必须独占一段**：它和生物 / 政治 / 地理 / 物理全冲突，只剩历史不冲突，
而历史已与物理配对，所以 7 段是最少的。

**硬校验：同一个学生在同一个时段最多只能有一场考试。**

> 这个 7 段表由程序**自动推导**（按冲突关系做图着色，`deriveTimeSlots`），不写死；
> 学校以后新增组合，重新推导即可。也允许老师手工覆盖。

### 5.4 排考流程

```
① 读名单 → 解析选科 → 校验 3+1+2（首选 1 门、再选 2 门）
② 按组合把学生分组：物化生 / 政史地 / 物化政 / 物化地
③ 分组分房间：
     物化生 → 若干「常规理考场」（每组一套座位）
     政史地 → 若干「常规文考场」
     物化政 + 物化地 → 若干「非常规主考场」
   分组时优先让同一个行政班的学生分散（避免同班扎堆）
④ 每个房间排一次座位（现有求解器，输入 = 该房间的学生 + 该房间的全部时段科目）
⑤ 专用考场：
     物化政全体 → 政治专用考场（排一次座位）
     物化地全体 → 地理专用考场（排一次座位）
⑥ 汇总：每人一张「时段 → 考场 + 座位号」表
⑦ 校验：每人考场数 ≤ 3；同时段不撞场；8 邻域不同班
```

**关键点：每一步都只是「把一批考生喂给现有求解器」**，没有新算法。
第 ④ 步里「8 邻域不能同班」的约束，在跨组合混排时依然成立（同班同学可能选不同科）。

分房策略（由 `options.groupPreference` 决定，见 §5.4）：

- `"sameCombination"`（默认）：每个批次（组合）独占若干考场，一个考场里只有一个组合 → 监考表最干净；
  考场不够时**直接报** `CAPACITY_INSUFFICIENT`，不偷偷混排。
- `"fillRooms"`：先把当前考场填满再换下一个，省考场；只允许与**逐时段不冲突**的批次共用（同一时段最多一门科目），
  共用时**合并成一套座位方案**（学生并集、一次 `plan()`、座位号唯一）并报 `ROOMS_SHARED` 警告。
- 两者都必须满足 §5.1 的硬规则，违反时报 `ROOM_SUBJECT_CLASH`。

> ⚠️ **分配失败时保留「已成功批次」的座位**：`sameCombination` 下考场不够时，已排上的批次仍会产出座位方案，
> 用于诊断「谁排上了、谁没排上」；但结果 `ok=false`（`CAPACITY_INSUFFICIENT` + 不导出名单）。
> 因此「已排人数 = 参考人数」**不等于**安排成功——判定成功只看 `ok`，以及每个学生**应考时段**是否都排满
> （专用考场可能只覆盖某个时段，例如物化生 40 + 物化政 20 只有 2 个普通考场时，物化政只拿到 T6 政治，
> T1–T5 仍是空的）。验收与网页判定都必须按「时段排满」，不要只数「有没有座位」。

> ✅ **多场次支持 `constraints`（限定）**：每套座位只下发「命中本座位学生 且 `roomId` 为空或等于本考场」的规则，
> `rows` / `cols` 由该考场自行解析（`first` / `last` / `door` / `window` 与「指定考场后的绝对号」都生效，§4.2）。
> `roomId` 会**参与分房**：被钉到某考场的学生所在批次优先、且只能进那个考场；装不下 / 与其它限定冲突 / 指向学生不会去的考场，
> 一律报 `CONSTRAINT_OVERSATURATED` / `RULE_INTERSECT_EMPTY` / `CONSTRAINT_EMPTY_DOMAIN`（error）并阻止导出，
> **绝不悄悄改成「不限考场」**。各套座位的未满足限定汇总进 `PlanAllResult.unmetConstraints`（带 `roomId` / `roomName`），
> CLI 摘要里单列一段「未满足的限定」。`CONSTRAINTS_IGNORED_MULTI` 仅作为历史码保留，正常路径不再产生。

### 5.5 考场的地点与专用科目

```ts
interface RoomSpec {
  id: string;
  name?: string; // 「第一考场」
  location?: string; // 「高二一班」「生物实验室」，老师自己填
  rows: number;
  cols: number;
  doorSide?: "left" | "right";
  note?: string; // 监考老师
  dedicatedSubjects?: string[]; // 专用科目，例如 ["politics", "geography"]
  combination?: string; // 专属组合考场：只接收这个组合的整批学生（本轮新增）
}
```

- `location` 出现在：监考表表头、座位网格表、网页考场配置页。
- **专用考场手工指定**：在考场配置里给考场打「专用科目」标记，工具把选了该科目的**非常规考生**
  整体安排进去。政治在 T6、地理在 T7，时间不冲突，**同一个房间可以既当政治专用又当地理专用**。
- **空考场取消**：排完之后如果某个考场一个学生都没安排上，`planAll` 会在 `emptyRooms` 里点名列出，
  CLI 也会打印「可取消的空置考场」。
  ✅ 已实现闭环：`--out-dir` 写出的 `job.json` 会自动剔除空置考场（`io` 的 `usedRoomIds` / `pruneEmptyRooms`，
  一个考场都没用到时安全阀不掏空配置），CLI 打印「已剔除空置考场：…」；网页第 ⑤⑥ 步按**求解结果**
  给出「一键移除空置考场」（作用于考场配置并提示重排）。

### 5.6 输出 A / 输出 B

> **本轮重做（按用户反馈：导出的 Excel 不像能打印的正式表）**。交付物是**两份合并工作簿 + 两个逐份文件目录**，
> 全部带字号 / 对齐 / 边框 / 合并大标题，并锁定 **A4 横向、一页宽**。实现见 §13 的 `io/src/xlsx.ts`。

**共通打印设置**（每个 sheet 都一样，写死在写出器里）：

| 项           | 值                                                                           |
| ------------ | ---------------------------------------------------------------------------- |
| 纸张 / 方向  | **A4（`paperSize="9"`）、横向（`orientation="landscape"`）**                 |
| 缩放         | `fitToWidth="1" fitToHeight="0"`（宽压到一页，纵向不限页）                   |
| 冻结         | 冻结前 **3** 行（大标题 / 小字 / 表头）                                      |
| 每页重复打印 | 第 **1–3** 行（`_xlnm.Print_Titles` = `1:3`）                                |
| 页边距       | 0.3 / 0.3 / 0.4 / 0.4 英寸，水平居中                                         |
| 列宽         | 按内容算（CJK 记 2 字符宽），总宽超过 **A4 横向可用宽 ≈ 27.8cm** 时等比收窄  |
| 对齐         | 大标题 / 表头居中；**正文数据格一律水平 + 垂直居中**；只有 `meta` 小字左对齐 |

**输出 A：按班级（给学生和班主任）**

- **合并工作簿** `按班级考场安排.xlsx`：sheet 1 =「**总表**」（全校，按班级 + 学号排序），之后**每班一张 sheet，sheet 名 = 班级名**；
- **逐份文件目录** `按班级考场安排/<班级>.xlsx`：每班一个文件，内容就是该班那张 sheet；
- 列：`班级 | 姓名 | 准考证号 | 主考场 | 主考场地点 | 单科考场1 | 单科考场1地点 | …`
  —— **每个考场列后面紧跟一列它的「地点」**，单科考场列按实际用到的最大数出现（用不到就不出）：

| 班级      | 姓名 | 准考证号 | 主考场   | 主考场地点 | 单科考场1            | 单科考场1地点 | 单科考场2 | 单科考场2地点 |
| --------- | ---- | -------- | -------- | ---------- | -------------------- | ------------- | --------- | ------------- |
| 高三(7)班 | 李娜 | 20240202 | 第三考场 | 高二一班   | 第二十考场（政治）   | 生物实验室    |           |               |
| 高三(9)班 | 王强 | 20240303 | 第五考场 | 高一·四班  | 第二十一考场（地理） | 录播教室      |           |               |

- **班级列每行都要填**（不再只写第一行）；
- **主考场列只写「第N考场」**（不带括号）；**单科考场列**才写 `第N考场（科目、科目）`，
  科目用全名、多科用「、」连接。主考场 = 该生座位时段最多的那个考场（并列取 `byStudent.rooms` 里靠前的）；
- 考场名用 `baseRoomName` 去掉 job 里那些「（语史政数英地）」后缀，标题里也不出现两个括号；
- **地点列**取该考场在这名学生那套座位里的 `location`；缺失时退回 `job.rooms[].location`，再缺留空
  （`roomLocation()`）。表头文案就是列名本身（`主考场地点`、`单科考场1地点`…）。

**姓名：默认不截断，只在整表超 A4 时才截**

- 先按**完整姓名**算整表宽度：**不超过 A4 横向可用宽（≈27.8cm）就原样输出**，一个字都不动；
- 只有超宽时才把**所有超过 5 个字的姓名**截成前 5 个字（按**码点**切，不会切半个字），仍超再由列宽等比收窄兜底；
- 截断与否按**全年级**判断（`fitNamesToA4` + `withHeaderRow`），所以总表、每班 sheet、单班文件三处口径一致，
  同一学生在各处显示相同；监考表独立判断（它的姓名列下标不同）；
- ⚠️ **同名风险**：截到 5 个字可能出现重名（真实数据里就有 1 组），**靠准考证号列区分**，别只看姓名；
- 真实数据实测：706 人、31 个姓名超过 5 字、最长 13 字，但总表「表头 + 正文」只有 **19.24cm ≤ 27.8cm**，
  所以 **`truncatedNames === false`**（不触发截断）。
  ⚠️ 算宽度时**不含 A1 合并大标题那一行**（`withHeaderRow` 只拼表头 + 正文）：把标题算进去会得到 ~29.2cm 的假超宽。

**输出 B：按考场（给监考老师）**

- **合并工作簿** `考场监考表.xlsx`：**每套座位一张 sheet**，sheet 名 = `第N考场（语数外物化生）`
  （考场名用 `baseRoomName`，括号里是该套座位要考的科目：多科用单字简称、单科用全名如「政治」）；
- **逐份文件目录** `考场监考表/<sheet 名>.xlsx`：每个考场一个文件（例如 `第一考场（语数外物化生）.xlsx`）；
- 表内大标题与 sheet 名同文案；第二行小字：`地点：<location> ｜ 考场人数：N`，
  该考场放宽了同班相邻时再补 ` ｜ 本考场已放宽同班相邻`；**不再有「监考：…」**；
- 正文表头 `座位号 | 班级 | 姓名 | 准考证号 | 备注`，按座位号排序；**正文格水平 + 垂直居中**；
  备注只有两种、**不带时段 / 不带「借考」字样 / 不带括号**（见下方 v3 规则），其余留空；
- 同一考场**不同时段考不同科目**时拆成多张 sheet，各自把科目写进标题：
  「第十九考场（政治）」「第十九考场（地理）」。

```
第一考场（语数外物化生）                    ← 合并大标题（16pt 加粗居中）
地点：高二一班 ｜ 考场人数：42 ｜ 本考场已放宽同班相邻
座位号 | 班级        | 姓名   | 准考证号 | 备注
  1    | 高三(1)班   | 张伟   | 20240101 |
  2    | 高三(5)班   | 李娜   | 20240202 |
  3    | 高三(1)班   | 张伟   | 20240101 | 不考：生物
  4    | 高三(7)班   | 王强   | 20240303 | 只考：生物
```

> 样式档位（`XlsxStyleName`）：`title`（16pt 加粗居中）/ `subtitle`（12pt 加粗）/ `meta`（9pt 灰字**左对齐**）/
> `header`（11pt 加粗居中 + 浅灰底 + 细边框）/ `body`（11pt **居中** + 细边框）/ `note`（9pt 灰字）。
> 正文**只有 `body` 一档**（全部居中），不再保留左对齐 / 居中两套，避免同一张表混用两种对齐。

#### 备注列规则（v3，老师三轮反馈后定稿）

考场表列的是**用过这间考场的人**，但每个时段真正应到的只是其中一部分——不标的话监考老师会把不考的学生当成缺考。
所以备注只有两种，且**一律不带时段、不带「借考」字样、不带括号**：

| 情形                                                         | 备注           | 例                                    |
| ------------------------------------------------------------ | -------------- | ------------------------------------- |
| 本考场是**主考场**，但该生缺其中某科                         | `不考：<科目>` | `不考：生物`                          |
| 本考场**不是**主考场（外来单科借考），且没考满全场           | `只考：<科目>` | `只考：生物`；多科 `只考：生物、地理` |
| 外来但**考满该考场全部科目**（如政治单科房间里的物化政学生） | **不写**       | 没有信息量，不加噪音                  |
| 正常全考（主考场里该考的都在这里考）                         | **不写**       | —                                     |

- **主考场 = 该生考「语数外」的那间考场**（老师：「毕竟语数外算是一个学生的主考场」）；
  取不到语数外信息时（单场 / 数据缺失）退回「座位时段最多的那间」。
  **班级表的「主考场」列与这里的判定共用同一个函数**（`studentMainRoomId`），所以两处口径永远一致。
- 多科目用「、」连接，顺序按 core 的科目固定顺序（`SUBJECT_DISPLAY_ORDER`）。
- **判定是数据驱动的**：用 `byStudent[].slots[].roomId` 反推「他在这间考场实际考了哪几科」，
  **绝不能拿 `students[].subjects` 相减**——那份只有 3 门选科，不含语数外。
- ⚠️ **只有监考表的备注去掉了时段**；CLI 摘要与网页的「借考明细」**仍然保留时段**
  （如「某生 T6 生物 → 第十八考场」），那是给人看走位的，不是给监考老师看的。
  见 §5.8.2 与 §16 的 v8.3。
- **真实数据实测**（706 人 / 20 张 sheet）：**只有 2 张**有备注——
  第十八考场（语数外物化生）34 行 = 22 行 `不考：生物` + 1 行 `只考：生物`；
  第十七考场（语数外政史地）29 行 = 1 行 `不考：地理`（该生组合史生政，地理在任何考场都没考——**这是正确行为，不是 bug**）；
  第十九考场（政治 / 地理）与 R1–R16 全干净。备注列宽 11.65cm / 10.54cm，都 ≤ 27.8cm。

> **分组规则**：同一考场 × 同一批考生的时段合并成一张表；常规考场各 1 张，
> 专用考场按科目拆（政治 / 地理各 1 张）。万一某考场混了批次（只在 `fillRooms` 且两批逐时段不冲突时，
> §5.1 硬规则），合并成一套座位后仍出 **1 张**，标题 = 考场名（科目并集）。
> 空结果时仍有安全阀（一张「无安排」sheet），不会写出空工作簿。

**输出 C：本期不做**（每人对照卡 / 校验报告）。`planAll` 已经返回 `byStudent` 与校验结论，
以后想加只差一个导出函数。

### 5.5.1 专属组合考场：`RoomSpec.combination`

> 老师原话：「**指定一个专属的老文科考场，让考政史地的整批学生集中在这个考场**。」

```jsonc
{ "id": "R9", "name": "第九考场", "rows": 7, "cols": 6, "combination": "史地政" }
```

- **语义**：这个考场只接收 `students[].combination` 等于该值的**常规组合批次**（整批进、全程不换考场），
  其余学生不会被分进来；仍然遵守「一室一时段一卷」（§5.1 硬规则不可破）。
- **写法任意**：`史地政` / `政史地` 等价，内部走 `normalizeCombination` 归一（`util.ts` 的 `roomCombination`）。
- **允许多间钉同一组合**：人数超过单室容量时，按 `rooms` 顺序依次吃下；
  仍然装不下就走既有缺路 `CAPACITY_INSUFFICIENT`（**绝不混排**）。
- **与专用科目互斥**：同时写了 `combination` 与 `dedicatedSubjects` 时**组合优先**，
  该考场不再进专用科目池，并报 `ROOM_COMBINATION_IGNORED_DEDICATED`（warning）。
- **与「限定」的关系**：这是**等价入口**——「限定里把该组合 `roomId` 钉到某考场」和「考场写 `combination`」
  排出来的结果一致，**连座位号都相同**（`core/test/room-combination.test.ts` 把这条等价性钉死）。
  老师面向前者更直观，AI 两种都能用；但显式 `roomId` 限定**优先**于专属组合
  （被 `roomId` 钉走的学生不受专属组合约束）。
- **诊断**：`ROOM_COMBINATION_APPLIED`（info，留痕哪个考场吃下了哪个组合）、
  `ROOM_COMBINATION_UNKNOWN`（warning，名单里没有该组合 → 该考场空置但结果仍 `ok`）。
- **单场模式下的行为**：专属组合是**多场次概念**（单场所有人考同一份卷子，没有「按组合分流」可言），
  所以单场 `plan`（`--single` / 名单没有选科）会**忽略该字段但绝不静默**：
  逐考场报 `ROOM_COMBINATION_IGNORED_SINGLE`（warning），消息形如
  「单场模式下所有考生考同一份卷子，**第一考场**的专属组合「政史地」不生效（按普通考场处理）」。
  此时结果仍然 `ok`、退出码 `0`（不再报误导性的 `SEARCH_FAILED`），CLI 成功时也会把这条 warning 打到终端；
  单场 `validate` 也不会因为该字段报 `MISMATCH` / `UNMET`（多场次行为不变）。

**独立校验**（`validate` / `validateAll` 重算，与求解器分开实现）：

| issue 码                    | 级别  | 触发                                                                         |
| --------------------------- | ----- | ---------------------------------------------------------------------------- |
| `ROOM_COMBINATION_MISMATCH` | error | 专属考场里坐了**别的组合**的学生                                             |
| `ROOM_COMBINATION_UNMET`    | error | 该组合的学生主考场**不在**钉住的专属考场里（被显式 `roomId` 钉走的学生放行） |

### 5.8 考场级「加限制 / 放宽限制」（本轮实现契约）

> 需求来源：老师 2026-09/10 的口述需求（结论已并入本文）。**红线不变**：一个考场、一个时段、只能有一张卷子。
> 下面 4 项都是**考场级 / 学生级的开关**，互不影响；每一次放宽都要在 `plan.json` 留一条 diagnostic，并在监考表上标注。
>
> **状态：✅ 已实现**（S9 / S10）。逐条依据：`core/src/plan-all.ts`、`core/src/schedule.ts`、`core/src/validate.ts`、
> `core/src/numbering.ts`、`core/src/model.ts`；测试 `core/test/borrow-relax.test.ts`、`core/test/nonrect.test.ts`。

#### 5.8.1 考场级放宽「同班相邻」：`RoomSpec.relaxSameClass`

| 写法              | 含义                                                                                |
| ----------------- | ----------------------------------------------------------------------------------- |
| 缺省 / `false`    | 按原规则（`maxSameClass`，见 §4.1 与 `numbering.ts`）                               |
| `true`            | 本考场完全放开：同班相邻不算冲突，该考场人数上限 = 座位数                           |
| 数字 n（如 `30`） | 本考场同班学生数上限 = n（用于 `CLASS_LIMIT_EXCEEDED`）；该考场同班相邻同样不算冲突 |

- `precheck` 的班级上限按 `Σ 各考场有效上限` 计算；放宽考场用 n（或座位数）参与求和，并报 `ROOM_SAME_CLASS_RELAXED`（warning）。
- 求解器与独立校验器都**跳过**放宽考场内的「相邻同班」判定（校验器报 `ADJACENCY_RELAXED` warning，不再是 error）。
- 单场 `PlanResult.level` 变 `roomRelaxed`；多场次结果 `PlanAllResult.relaxedRooms` 列出这些考场，监考表表头标注「本考场已放宽同班相邻」。

#### 5.8.2 按科目借考：`Student.subjectRoom`

```jsonc
{
  "id": "<借考生学号>",
  "name": "某生",
  "subjects": ["biology", "politics", "history"],
  "subjectRoom": { "biology": "R18" },
}
```

- 语义：**这个学生的这门科目到指定考场考试**，该时段占用目标考场的一个空位；其余科目仍在自己的主考场。
- 硬规则照旧按「考场 × 时段」判定：目标考场该时段**只能**开考这一科（空着也算可以开考这一科）；若该时段另有别的科目 → `SUBJECT_ROOM_CLASH`（error，不导出）。
- 目标考场必须已有座位方案（否则 `SUBJECT_ROOM_NO_SEAT`，error）；借考学生在该座位方案里用 `SeatingPlan.borrowedSubjects[studentId]` 登记「只考这些科目」，避免占用他其它时段的座位。
- ⚠️ **监考表备注不带时段**（v3，§5.6）：只写 `不考：X` / `只考：X`；而**这里的「借考明细」保留时段**
  （`borrowings` 与 CLI 摘要仍是「某生 T6 生物 → 第十八考场」）。两边用途不同，别以为是同一个口径。
- 借考生**会被并入目标座位方案的 `studentIds`**（他的座位就在这套方案里），所以看「某考场几个人」时要连借考生一起数；
  区分方式是 `SeatingPlan.borrowedSubjects` / `PlanAllResult.borrowings`，不是 `studentIds` 里有没有他（§5.8.6 实测 R18 = 34）。
- `byStudent[student].slots[slotId]` 指向目标考场 + 座位号，`distinctRooms` 计入 `maxRoomsPerStudent`。
- **借考的座位同样受行列限定约束**：借考生在该生**不带 `roomId`** 的行 / 列限定下也要坐对位置
  （例如「2517 全班靠门第 1 列」的 `cols: ["door"]`，对他在 R18 的借考座位同样生效）。
  同理，`subjectRoom` 指向的考场不能与该生的 `roomId` 限定打架。
- **自动优待**（老师原话的精神）：被 `roomId` 钉在主考场 R 的学生，若 R 的那套座位在该时段**本来就开考这一科**，就留在 R 考，不必专门去专用考场——同一时段仍然只有一张卷子。所以某生的「政治」留在 R17（与史地政同场），只有「生物」需要 `subjectRoom` 借考到 R18。
- 诊断：`SUBJECT_ROOM_APPLIED`（info，逐条留痕）、`SUBJECT_ROOM_UNKNOWN_ROOM` / `SUBJECT_ROOM_UNKNOWN_SUBJECT` / `SUBJECT_ROOM_CLASH` / `SUBJECT_ROOM_NO_SEAT`（error）。

#### 5.8.3 显式时段表：`options.slots` / `options.forbiddenSameSlot`

- `options.slots: [{ id?, name?, subjects: [...] }, …]`：给了就**不再自动推导**（老师按考务表填死 7 个时段）；id / name 缺省按顺序补齐；同一学生在同一时段被排两科 → error。
- `options.forbiddenSameSlot: [["chemistry","biology"], …]`：只补「必须分开」的科目对，其余仍自动着色。两者都给时以 `slots` 为准。
- 采用显式时段时留一条 `SLOTS_PROVIDED`（info），便于事后核对。
- 名单被手工剔除后自动推导会塌陷（政治/地理被并进同一时段），显式时段是正式解法。

#### 5.8.4 非矩形考场：`RoomSpec.extraFrontSeats`

- `extraFrontSeats: [2, 4]` = 第 2、4 业务列在讲台一侧各加 1 座；`roomCapacity = rows × cols + extraFrontSeats.length`（5×7+2 = 37）。
- 编号：仍按列蛇形，但每列座位数 = `rows + 该列是否加座`；加座永远是该列最后一个号，行号记 `0`（第 1 排之前）。37 座 → 第 1 列 1–7、第 2 列 8–15（15 = 加座）、第 3 列 16–22、第 4 列 23–30（30 = 加座）、第 5 列 31–37（详见 §4.5）。
- 邻接：加座与同列第 1 排、相邻列第 1 排相邻（8 邻域）；4 邻域只算同列第 1 排；两个加座之间不相邻。
- `maxSameClass` 按**真实座位图**算（4 邻域 = 二分图最大独立集；8 邻域 = 实际图的最大独立集），不再用 `⌈rows/2⌉×⌈cols/2⌉`。
- 行 / 列限定**不能**指向加座（加座不算第 0 排、`last` 仍是第 `rows` 排）；加座只由求解器自然填充。

#### 5.8.5 分房游标 bug（`allocateDemands`）

被 `classes: ["2518"]` 这类「整批钉考场」拆出「钉住的 + 未钉住的」两段时，未钉住的那段原来只能从 `cursor` 往后扫，
扫到 rooms 末尾就报 `CAPACITY_INSUFFICIENT`。修正后：游标扫到末尾会**回卷**到 0 再扫一遍（同一次回卷内还找不到才判缺座），
且 `sameCombination` 下**同一个原始批次**拆出的两段允许共用同一考场，于是未钉住的 6 人回到 R17。

#### 5.8.6 本轮验收目标（真实 job：706 人 / 19 考场）—— ✅ 实测通过

在 `out/job.intent2.json`（706 人 / 19 考场 / 12 间 42 座 + 7 间 35 座）上给 R17 加 `relaxSameClass`、
某生（2517，史生政，被 `roomId` 钉到 R17）加 `subjectRoom: { biology: "R18" }`，**实测**结果：

| 考场   | 实测                 | 说明                                                                                                                                           |
| ------ | -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| R1–R16 | 物化生 644           | 正好坐满                                                                                                                                       |
| R17    | **29 人**            | 2518 的 22 + 2517 的史地政 6 + 某生；`relaxedSameClass = true`                                                                                 |
| R18    | **34 人**            | 物化政 13 + 物化地 9 + 物化生 11 = 33，**外加**某生（T6 借考生物，落在 R18 靠门列 1 号）；`borrowedSubjects = { "<借考生学号>": ["biology"] }` |
| R19    | 政治 **13** + 地理 9 | 某生的政治在 R17 考（主考场本来就开考政治），不进专用考场                                                                                      |

`ok = true`、`emptyRooms = []`（19 个考场全用上）、`overRoomLimit = []`、`validate` → 退出码 0；
`relaxedRooms = ["R17"]`，`borrowings` 一条（某生 生物 → R18 **1 号**，靠门列 —— 借考座位同样吃「不带 `roomId` 的行列限定」）；
`ROOM_SAME_CLASS_RELAXED`（warning）、`ROOMS_SHARED`（warning）、`SUBJECT_ROOM_APPLIED`（info）各按预期出现。

> ⚠️ 与需求文档的差异：需求写「R18 = 33 人 + 某生 T6 借考」，实测 **`studentIds` 是 34**——
> 借考生会被并入目标座位方案的 `studentIds`（因为他的座位就在这套方案里），
> 用 `SeatingPlan.borrowedSubjects` 区分「借考」而不是把他算在外面。R18 的 34 ≤ 35 座，不超容。
> 另外注意：跑真实 job 前要先把 core/cli **重新构建**（`pnpm build`），`packages/cli/bin/exam-seat.mjs`
> 走的是 `dist/`，没构建时会拿旧包、看不到放宽与借考。

## 6. 求解算法

### 6.1 单场：带定义域的分配问题

每个学生有可用座位集合，每座位至多 1 人，目标为「同考场内相邻（默认切比雪夫距离 1）的两个座位班级不同」。
规模约 1000 人 / 30 考场。

```
1. 建座位表（蛇形编号）
2. 算定义域：学生 → 可用座位集合（选择器 + rows/cols 编译出来的结果）
3. 贪心初始解：按定义域大小升序处理（MRV），挑邻居已用班级最少的座位
4. 模拟退火：
   move A 同考场内交换两人（主力）
   move B 跨考场交换两人（调整班级分布）
   交换后两人必须仍落在各自定义域内
5. 成本（增量维护，每次交换只重算两个座位的邻域，O(1)）：
   cost = 1000 × 相邻同班对数 + 10 × 单考场同班超限 + 1 × 考场人数不均衡
6. 按考场序号依次填满；末场可不满，其后考场整场空置
```

**可行性守卫**：容量合计 ≥ 参考人数；单考场单班上限按**该考场真实座位图的最大独立集**算（`numbering.ts` 的 `maxSameClass`：
35 座（5×7）king ≤ 12 / orth ≤ 18、42 人场（6×7）king ≤ 12 / orth ≤ 21、37 座加座场 king ≤ 12 / orth ≤ 20，见 §4.5.3 与 `core/test/nonrect.test.ts`）；
标了 `relaxSameClass` 的考场改用该考场自己的上限（`true` = 座位数，数字 = 该数字）且不计入相邻同班；每条限定可用座位数 ≥ 该组人数；交集非空。

> 数学背景：座位图是国王图，色数 4；退化到 4 邻域后是二分棋盘图，色数仅 2，**≤8 个班几乎必然可解**。

### 6.2 多场次 = 多次调用同一个求解器

`planAll` 不含新算法：它做的是「分组 → 分房 → 每个座位方案调一次 `plan` → 汇总 `byStudent`」。
所以单场的所有保证（可复现、诊断、独立校验）在多场次里同样成立，每个 `SeatingPlan.result` 都是一份完整 `PlanResult`。

### 6.3 可复现性

- `core` 全同步纯函数，**同输入同 seed 必得同结果**（验收脚本有「同 seed 结果可复现」断言）；
- 随机来源只有 `mulberry32(seed)`，不用 `Math.random`；
- `inputFingerprint`（canonical JSON 的 sha256）用于判断结果是否还对应当前输入。

这是让 AI 能「自己修好再重跑」的关键，也是网页「一键应用建议」的实现方式。

### 7.2 搜不出来时

报告指出**最紧的地方**：哪个考场哪个班超了多少、冲突座位号、涉及班级，
然后给出可一键应用的建议（把该考场改成大考场 / 调走 N 人 / 放宽限定 / 降级重排）。
`SEARCH_FAILED` 的 `evidence` 里给 `bottleneck`（逐考场的班级负载）、`conflicts`、`unmetConstraints`。

### 7.3 降级阶梯（必须显式确认）

| 级别              | 内容                           | 触发                            |
| ----------------- | ------------------------------ | ------------------------------- |
| **L0 严格**       | 8 邻域 + 限定硬约束            | 默认                            |
| **L1 四邻域**     | 只要求前后左右不同班           | **班级数 ≤ 8 自动**；否则需确认 |
| **L2 限定软化**   | 限定降为高权重惩罚，求违反最少 | 老师确认                        |
| **L3 最少冲突**   | 允许同班相邻，最小化冲突并标红 | 老师确认                        |
| **L4 结构性建议** | 不降级，改给容量/布局建议      | 自动兜底                        |

降级结果页挂**黄色横幅**，写进 `level` 字段和导出的「校验报告」表，CLI 用退出码 `2` 表达。
L2/L3 **只把「限定太紧」降级为惩罚**；结构性错误（座位不够等）仍然判死。

> `level` 还有第五个取值 **`roomRelaxed`**：考场级放宽过「同班相邻」（`RoomSpec.relaxSameClass`，§5.8.1）。
> 它不是求解器降级，而是**老师明确指定的放宽**，优先级高于「班级数不足自动退化」的 `orthogonal`；
> 同样照常导出、同样要主动告诉用户，并在监考表表头标注。

### 7.4 校验器的码（`ValidationIssue.code`，字符串）

独立校验器与求解器**分开实现**，它的码不在 `DiagnosticCode` 里：

- `ADJACENCY_CONFLICT`、`CONSTRAINT_UNMET`
- `ROOM_COMBINATION_MISMATCH`（专属考场里坐了别组合的人）、
  `ROOM_COMBINATION_UNMET`（该组合的学生主考场不在钉住的专属考场里；被显式 `roomId` 钉走的学生放行）——都是 error（§5.5.1）。
  两者都**只在多场次**判定；单场因为该字段被忽略（见 `ROOM_COMBINATION_IGNORED_SINGLE`），不报这两条
- `ADJACENCY_RELAXED`（warning）：该考场标了 `relaxSameClass`，校验器**跳过**了它的相邻同班判定；
  不计入 `ok=false`，但必须在结果里留痕（§5.8.1）
- `ENTRY_*`：`ENTRY_DUPLICATE_SEAT`、`ENTRY_DUPLICATE_STUDENT`、`ENTRY_MISSING_STUDENT`、
  `ENTRY_NUMBERING_MISMATCH`、`ENTRY_PHYSICAL_COL_MISMATCH`、`ENTRY_SEAT_OUT_OF_RANGE`、
  `ENTRY_UNKNOWN_ROOM`、`ENTRY_UNKNOWN_STUDENT`

## 8. 校验与导出

- **独立校验器**（`validate(job, result)`，与求解器分开实现）：重验容量、邻域约束、每条限定、编号一致性。
  任何一条不过 → 拒绝导出。
- **单场导出**（`@exam-seat/io`）：
  - `buildPlanWorkbook()` → `考场安排名单.xlsx`，三张表：`考场安排名单`（考场 / 座位号 / 学号 / 姓名 / 班级）、
    `按班级`、`校验报告`（含是否降级、诊断、冲突与未满足限定）；
  - `buildRoomSheets()` → `考场座位表.xlsx`，逐考场一张网格表，方便贴门口。
- **多场次导出**（`@exam-seat/io`，规格见 §5.6）：
  - `buildClassScheduleWorkbook(result, rooms, options?)` → `按班级考场安排.xlsx`（总表 + 每班一张 sheet）；
  - `buildInvigilatorWorkbook(result, rooms?)` → `考场监考表.xlsx`（每套座位一张 sheet）；
  - 另有 `buildClassScheduleRows` / `buildClassScheduleSheets` / `buildInvigilatorSheets` 供网页复用（返回结构化行 / sheet 规格）；
    这些函数在 `io/src/schedule-export.ts`，写出器在 `io/src/xlsx.ts`；`buildClassScheduleRows` 还会返回 `truncatedNames`，告诉调用方这次有没有截姓名；
  - 两者都走 §13 的零依赖写出器，带 A4 横向 + 冻结 + 重复表头 + 自动列宽；
  - `--out-dir` 还会把每个班 / 每个考场各写一份**独立文件**到 `按班级考场安排/` 与 `考场监考表/` 子目录（见 §9）。
- 导出前强制跑一次 `validate()`，这是 CLI 与 Web 共用的安全闸门。CLI 的 `exam-seat validate` 不过就退出码 `3`；
  网页会先拦一道，老师坚持时只能「仍然导出（仅供人工微调）」并在界面上说清楚。

### 8.1 什么时候**不**导出名单 / 监考表

`--out-dir` 默认会写名单与监考表；只有下面这类**结构性**问题才拒绝写（`plan.json` 与 `job.json` 照写，留痕）：

| 判定           | 包含的诊断码                                                                                                                                                                                                                                                                                                                                                                                            | 理由                                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| **阻止导出**   | `ROOM_SUBJECT_CLASH`、`CAPACITY_INSUFFICIENT`、`NO_STUDENTS`、`NO_ROOMS`、`INVALID_ROOM_SIZE`、`STUDENT_DUPLICATE_ID`、`STUDENT_MISSING_CLASS`、`CLASS_LIMIT_EXCEEDED`、`SEAT_CONFLICT`、`UNKNOWN_ROOM_ID`、`CONSTRAINT_*`、`RULE_INTERSECT_EMPTY`、`SUBJECT_ROOM_UNKNOWN_ROOM`、`SUBJECT_ROOM_UNKNOWN_SUBJECT`、`SUBJECT_ROOM_CLASH`、`SUBJECT_ROOM_NO_SEAT`、`SUBJECT_ROOM_NO_SLOT`、`SLOTS_CONFLICT` | 这些是「名单本身不成立」，交出去会误导老师                                                              |
| **不阻止导出** | `SEARCH_FAILED`、`TOO_FEW_CLASSES`、`ROOMS_SHARED`、`ROOMS_OVERPROVISIONED`、`CONSTRAINTS_IGNORED_MULTI`、`STUDENT_MISSING_NAME` / `STUDENT_MISSING_SUBJECTS`、`UNKNOWN_STUDENT_ID`、`ABSOLUTE_ROWCOL_WITHOUT_ROOM`、`ROOM_SAME_CLASS_RELAXED`、`SUBJECT_ROOM_APPLIED`、`SLOTS_PROVIDED`                                                                                                                | 这些是**主动选择的降级**或提示：`--relax` 本来就是要「违反最少」并交付，强行拦下来会把 L2/L3 这条腿打断 |

- 核心 API：`core` 导出 `blocksListExport(diagnostics)`，CLI 单场与多场次共用同一条判据；判为阻止时 stderr 明确说明
  「结果未通过校验，已只导出 plan.json / job.json，未导出名单与监考表」并逐条列出 error 诊断。
  码表以 core 的 `BLOCKING_EXPORT_CODES` 为准（与 §7.1 一样，文档与实现不一致时以代码为准并回写本文档）。
- 降级（`level != "strict"`，退出码 `2`）**照常导出**，但必须挂黄色横幅 / 写进「校验报告」表，
  `stats.conflicts` 与 `unmetConstraints` 是谁都能核对的硬证据。
- 网页同一套语义：拦一道并说明原因，老师坚持时可「仍然导出（仅供人工微调）」。

### 8.2 多场次的独立校验：`validateAll`

`validate(job, result)` 只认单场 `PlanResult`。多场次（`plan.json` 里含 `seatings`）走 **`validateAll(job, result)`**：

```ts
interface PlanAllValidation {
  ok: boolean;
  seatings: {
    roomId;
    roomName;
    subjects: string[];
    seats: number;
    ok: boolean;
    report: ValidationReport;
  }[];
  hardRuleClashes: RoomSubjectClash[];
  issues: ValidationIssue[]; // 汇总
}
```

- **逐 seating 重建子 job**（该考场的房间 + 该套座位的考生 + 相应限定），调用同一份单场 `validate()`；
- **限定是否真的满足独立复核**：把每个学生的座位按他自己那套座位的考场重算 allowedSeats，**不复用 `planAll` 的中间结果自证**；
- **硬规则独立推导**：从 `byStudent[].slots` 自己数「考场 × 时段」的科目数，不调用 `findRoomSubjectClashes`；
- 另查座位唯一（`(room,slot,seatNo)` 撞号）、`byStudent` 与座位方案编号一致、应考却没排上（`ENTRY_MISSING_STUDENT`）；
- `seatings` 为空 → `NO_STUDENTS`（error），**不真空通过**（与 `planAll.ok` 同口径）；
- CLI：`exam-seat validate --job job.json --plan plan.json` 多场次输出每套座位结论 + 汇总，`ok` → 退出码 `0`，否则 `3`。

> 这一条是本项目的交付底线：**多场次结果必须能被独立验证**。`planAll().ok === true` 不等于通过，
> 必须 `validateAll().ok === true`，验收脚本再用自己的推导核一遍（§14 口径）。

## 9. CLI

```bash
exam-seat roster    --file roster.xlsx [--sheet 名称] [--absent 缺考名单.xlsx] [--absent-sheet 名称] [--out roster.json]
exam-seat rooms     --spec "1-20:small,21-25:large,26:6x4" [--json]
exam-seat numbering --rows 6 --cols 5 --door right
exam-seat template  [--out job.template.json]
exam-seat precheck  --job job.json [--json]
exam-seat plan      --job job.json [--out-dir out] [--json] [--single]
                    [--seed N] [--relax 模式] [--adjacency 模式] [--force-king]
                    [--time-limit ms] [--show N]
exam-seat validate  --job job.json --plan plan.json
```

约定（**为 agent 设计**）：

| 项          | 约定                                                                                                                                                                          |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--job -`   | 从 stdin 读 job.json，AI 可以不落临时文件直接管道传入                                                                                                                         |
| `--json`    | **stdout 只输出一个 JSON 对象**；进度与日志全部走 stderr                                                                                                                      |
| 退出码      | `0` 完美 ｜ `2` 已降级 ｜ `3` 预检失败 / 排不出来 / **结构性 error**（名单不成立，如 `CAPACITY_INSUFFICIENT`、`ROOM_SUBJECT_CLASH`）｜ `1` 用法或 IO 错误                     |
| 幂等        | 同 `--job` + 同 seed → 同输出                                                                                                                                                 |
| `--out-dir` | 单场写 `考场安排名单.xlsx` / `考场座位表.xlsx` / `plan.json` / `job.json`；多场写 `按班级考场安排.xlsx` / `考场监考表.xlsx` / `plan.json`                                     |
| 单场 / 多场 | 名单里带选科（`combination` 或 `subjects`）自动走 `planAll`；`--single` 强制按单场处理                                                                                        |
| `validate`  | 单场 `plan.json` 走 `validate()`；多场次（含 `seatings`）走 `validateAll()`，逐 seating 重建子 job 重验并独立核对「同一考场同一时段一科」、座位唯一、限定是否真的满足（§8.2） |

退出码让 agent 能直接分支：拿到 `3` 就去读 `diagnostics[].suggestions`，拿到 `2` 就把 `level` 明确告诉用户。

`--spec` 语法刻意做得紧凑，方便 AI 拼：`1-20:small`、`21-25:large`、`26:6x4`（自定义）。

**尺寸口径已统一**（网页预设与 CLI / `template` 三处一致）：

| 写法               | 尺寸            | 容量    | 同班上限（king / orth） |
| ------------------ | --------------- | ------- | ----------------------- |
| `small`（或 `小`） | **5 列 × 7 排** | **35**  | 12 / 18                 |
| `large`（或 `大`） | 6 列 × 7 排     | 42      | 12 / 21                 |
| `NxM`              | N 排 × M 列     | `N × M` | 见 §4.5.3               |

`--help` 与错误文案都会写明尺寸（`small = 5 列 × 7 排 = 35 座，large = 6 列 × 7 排 = 42 座`）。

> ⚠️ **行为变更（2026-10）**：CLI 的 `small` **从 6×5=30 座改成了 7×5=35 座**（与网页一致）。
> **既有脚本/ job 里写 `small` 的，容量会凭空多 5 座**——如果想保持原来的 30 座，请显式写 `6x5`。
> 议题 13 已解决。

## 10. Web 应用

### 10.1 步骤条与数据流

六个步骤页由顶部的步骤条串起来（自研，不再用 `el-steps`），路由用 **hash**（纯静态托管甚至 `file://` 都能打开）：

```
导入名单 → 排除缺考 → 配置考场 → 设置限定 → 排考场 → 结果名单
                          ↕ 导入 / 导出 / 粘贴 job.json
```

状态用 Pinia 分成五个 store：`roster`（名单 + 排除）、`rooms`（考场）、`constraints`（限定）、
`options`（标题 / seed / 邻接 / 降级 / 时间上限）、`result`（结果 + 校验报告）。
每个 store 自己 `watch` 到 localStorage（键名前缀 `exam-seat:`），刷新不丢。

### 10.2 六个步骤页

**① 导入名单**
拖拽 / 选择 `.xlsx` → `readRoster` 解析；多表选表；列映射向导（`学号` / `姓名` / `班级` 必填，
`性别` / `选科` / `备注` 选填，可随时手改，改完立刻重解析，并保住已排除状态）；
列出问题行（重复学号、缺班级等）；顶部统计总人数 / 班级数 / 各班人数；
名单里带选科时另外给出**选科组合分布**，并提示多场次编排的现状。

**② 排除缺考**
表格 + 搜索（学号 / 姓名 / 班级，多条件模糊匹配，支持 `班级:高三(1)班` 这种字段限定）。
主路径：**查询 → 全选当前结果 → 批量排除**。被排除行置灰打「不参加」标签，抽屉可单条 / 全部恢复。
底部实时显示「应考 / 已排除 / **实际参考**」，容量校验一律按实际参考算。
排除状态就是 `Student.included = false`。

**③ 配置考场**
每行一个考场：名称、类型（大 6×7=42 / 小 5×7=35 / 自定义 行×列）、门的位置（默认靠右）、
**专用科目**、**专属组合**、**备注**（列序按老师习惯：专用科目在前、备注在后，备注不再标「（监考老师）」）。
「专用科目」空值 placeholder 是 **「常规考场」**；设了专属组合的考场会提示「不再走专用科目」（§5.5.1）。
「放宽同班相邻」在这里表达为**勾选框「放宽本考场」+「同班学生数上限」**：勾上后该考场内同班相邻不算冲突，
上限留空 = 不限（等价 `relaxSameClass: true`），填数字 = 该考场同班人数上限（§5.8.1）。
支持批量新建、上下移、重排考场号。容量不足红字告警「还缺 N 个座位」并给「补 N 个大考场」按钮；
容量过剩提示哪些考场会整场空置，给「删掉会空置的考场」按钮。
每个考场配**座位编号缩略图**（按物理列序画、门在右侧，所见即所得）。

**④ 设置限定**
筛选学生（复用同一套搜索）→ 勾选 → 添加限定。弹窗里：

- 考场限定（**单选**下拉，显示「第3考场（张老师）」）；
- 排 / 列：**没选考场时只列语义值，绝对号输入框整个隐藏**；选了考场才展开绝对号，`max` 绑该考场行列数；
- 「一键四角」预设（`行=[首,末]`、`列=[靠门,靠窗]`）；
- v2 选择器：**按班级 / 按组合 / 按科目**，与点名取并集，实时显示「命中 N 人」；
- 实时预览：可用座位总数、逐考场分布、语义值在各类考场的解析、选中考场的座位网格高亮。

规则列表可编辑 / 删除，用 `precheckJob` 做实时冲突检测，冲突项红字标出原因，
带建议的冲突可以「应用建议」直接改配置。

**⑤ 排考场**
先 `precheckJob`：有致命问题就停在这一页，原样展示 `diagnostic.message`，
并把 `suggestions[]` 渲染成按钮（点了就把其中的 JSON Patch 应用到 job 再自动重跑预检）。
预检通过后用 **Web Worker** 跑 `plan`，显示进度与已用时间，可取消；结果三态：
**完美**（`ok && level === "strict"`）/ **已降级**（黄色横幅标注 `level` 与原因）/ **排不出来**（诊断 + 建议）。
名单带选科时页面明确提示：多场次界面仍在实施中，本页按单场求解，需要多场次请用 CLI。

**⑥ 结果名单**
主输出就是名单表格：考场 / 座位号 / 学号 / 姓名 / 班级，按 `考场号 → 座位号` 升序；
可按班级、考场筛选，可搜「某人坐哪」；附**校验报告**摘要（`validate()` 的结论、冲突明细、未满足限定、诊断）；
导出 `考场安排名单.xlsx`（导出前校验不过会拦一道，只能二次确认强制导出）。
当配置改过、与结果的数据指纹不一致时，页面顶部提示「这份结果是旧配置算出来的，建议重排」。
座位网格只作页面预览。

### 10.3 job.json 双向互通与持久化

- **导出 job.json**：把当前配置拼成完整 v2 job（`jobVersion: 2`，含选科、地点、专用科目、选择器）；
- **导入 job.json**：文件选择或直接粘贴（方便把 AI 生成的 job 贴回来复核），解析失败给中文原因；
- **无损**：v2 字段、甚至 core 还不认识的 `options` 字段（如 `groupPreference`）都原样保留，往返不丢；
- **回灌**：诊断建议应用后会把整份 job 写回各个 store，保证「界面看到的 = 求解器看到的」；
- **持久化**：`localStorage`，键名前缀 `exam-seat:`；清空数据会把本应用的键全删掉（不动同域其它键）。

### 10.4 实现情况

- **表格虚拟滚动**（议题 1）：已实现。`web/src/components/VirtualTable.vue` 是**自研**虚拟表格
  （**不再依赖 `el-table-v2`**，见下方「组件库迁移」）：只渲染可视区 + 前后 `OVERSCAN = 4` 行，
  第 ①④⑤⑥ 步的四张表（含结果页主表）都走它；1000 行只渲染可见区（实测 1000 行 → **19 个 `.vt-row`** = 可视 10 行 + 前后各 4 行 overscan + 1；单测断言 `< 50`，
  表头「全选当前结果」仍勾中全量 1000 人）。对外 props / emit / `cell-<key>` 插槽与旧实现**保持一致**，
  所以调用点没有语义变化。
  考场配置页（第 ③ 步）是行内编辑表、且考场数量级很小（几十行），不走虚拟化，直接用 shadcn `Table`。

### 10.6 网页对外文案口径（老师面，不露内部术语）

网页是给老师用的，**不出现内部术语与原始数据**：

| 项                | 口径                                                                                                                                                                                  |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 品牌 / 页面标题   | **「考场排布」**（`web/index.html` 的 `<title>` 与顶栏）                                                                                                                              |
| `job.json` 的称呼 | 网页里叫 **「排布状态」**，下载名 **`排布状态.json`**（**仍是同一份 job.json**，导入按内容解析、兼容旧文件名）                                                                        |
| `plan.json`       | **网页不再导出**（CLI 仍写），结果只留在会话里                                                                                                                                        |
| 诊断展示          | 只显示 core 的中文 `message` + 中文级别（`error`→错误、`warning`→警告）；**不显示** `code`、原始 JSON `evidence`                                                                      |
| 降级级别          | 只显示中文说法（如「已降级：只要求前后左右不同班」「已放宽：本考场内同班相邻不算冲突」）；`softConstraints` / `minConflicts` 这类**只作为内部取值**（下拉选项的 value），标签一律中文 |

## 11. AI Skill

**位置（项目级，随项目打开生效）**：`.agents/skills/exam-seating/SKILL.md`

DSH 的发现规则：扫描根目录下的**直接子项**，`<name>/SKILL.md` 目录包或 `<name>.md` 平铺文件，
`name` 必须 kebab-case；嵌套 `**/SKILL.md` **不会**被发现。frontmatter 必填 `name` 与 `description`。

**容量约束**：`SKILL.md` 渲染后必须 < 8192 字符（当前约 5.5 KB），所以：

- `SKILL.md` 只放**入口信息和最短路径**（何时用、三步工作流、CLI 速查、高频坑位）；
- 完整字段表、诊断码全表、边界规则放进同目录 `reference.md`，由 SKILL.md 指路；
- 示例放进 `examples/job.sample.json`。

**三步工作流**：

1. **建模**：把用户的自然语言 / Excel 名单变成 `job.json`。名单用 office-xlsx skill 或 `@exam-seat/io` 读；
   需求翻译成 `rooms` 与 `constraints`。
2. **调用**：`exam-seat plan --job job.json --out-dir out --json`，读 stdout 的 JSON。
3. **解释与修复**：读 `diagnostics[]`（中文 `message` + `evidence` + 可应用的 `suggestions[].patch`）；
   `ok:false` 或 `level != "strict"` 时**必须先告诉用户**，不能默默交付。

**必须写死的坑位**：

- 列号**从靠门侧**起算，第 1 列 = 靠门列；不是从左往右。
- 考场限定是**单选**，不能给一个学生配多个考场。
- 同一学生多条限定**取交集**，不是覆盖。
- 班级数 ≤ 8 会**自动降级**为 4 邻域，`level` 变成 `orthogonal`，必须向用户说明。
- 输出是**名单**（考场 + 座位号），不是座位图。
- 名单带选科 ⇒ 自动多场次；交付物是「按班级考场安排.xlsx + 考场监考表.xlsx」；
  常规组合全程不换考场，非常规组合中途换一次；`--single` 才回到单场。
- 专用考场用 `dedicatedSubjects` 手工指定（可兼多科），只收非常规组合中考了该科目的学生。
- **一个考场、一个时段、只能考一科**（§5.1 硬规则，不可降级；违反报 `ROOM_SUBJECT_CLASH`，结果不得交付）。
- `options.groupPreference`：`sameCombination`（默认，一个考场只放同一组合）/ `fillRooms`（先填满考场，共用时合并座位并报 `ROOMS_SHARED`）。
- 多场次**支持** `constraints`：`roomId` 会参与分房（钉住的学生只能进那个考场）；满足不了会报 error 且不导出，别把 `unmetConstraints` 当成警告忽略。
- **考场级放宽只对本考场生效**：`relaxSameClass: true | 数字` 写在 `rooms[]` 上；会留 `ROOM_SAME_CLASS_RELAXED`，`level` 变 `roomRelaxed`，必须告诉用户。
- **借考不产生第二张卷子**：`student.subjectRoom` 只是「这个学生这科换个座位」，目标考场该时段仍然只能开考这一科；冲突报 `SUBJECT_ROOM_CLASH`。
- **加座不算排、不占行号**：`extraFrontSeats` 的加座行号为 0，`rows` / `cols` 与语义值 `last` / `window` 都按原矩形解析。
- **时段塌陷用 `options.slots`**：名单被手工剔除后自动推导可能把两科并进同一时段；按考务表写死 `slots` 才是正式解法。

> ✅ **现状**：`SKILL.md`（8172 字节 < 8192）与 `reference.md` 已覆盖 job.json v2 / 多场次 /
> `dedicatedSubjects` / `groupPreference` / 考场级放宽 / 借考 / 加座 / 显式时段与本轮全部新诊断码；
> `examples/job.sample.json` 是带选科样例，`exam-seat precheck --job` 可直接跑通。
> 本轮 skill 更新见 §16 的 v6.1 / v8.x 条目。

## 15. 已定事项

1. **Core 不发 npm**，只在本仓库内由 pnpm workspace 互相 link。
2. **AI 读 Excel 走 `@exam-seat/io`**，Node 与浏览器同一套代码，不依赖 Python。
3. **输出只做两种**：按班级（学生 / 班主任）、按考场（监考老师）；第三种本期不做。
4. **专用考场手工指定**：在考场配置里给考场打「专用科目」标记（`dedicatedSubjects`），可兼多科。
5. **常规组合全程不换考场**；只有非常规组合中途换一次（§5.1）。
6. **空考场自动上报可取消**（`planAll().emptyRooms`），导出 `job.json` 时自动剔除，网页可一键移除。
7. **job.json 是唯一契约**，字段语义只由 core 解释；网页与 CLI 不得私自扩展含义。
