# exam-seat 需求：考场级「加限制 / 放宽限制」

> 给开发者 agent 的改造需求单。所有结论都有实跑证据（命令 + 报错原文 + 代码位置），文末附复现材料。
>
> **两条先说清楚：**
>
> 1. **「一个考场、一个时段、只能发一张卷子」是硬规则，不放宽、不改。** 我一开始提过"允许考场同段多卷"的方案，**已撤回**；这条本来就写在 `docs/design.md` §5.1（「硬规则：一个考场，一个时段，只能考一科」，`design.md:509-513`），本次不动它，只把"个别学生换考场考试"的需求单独提出来（§3.3 借考）。
> 2. 目标排法在数学上完全排得下（小教室按 35 座 = 749 座；按真实 37 座 = 763 座；参考 706 人）。现有选项差 **三个必备能力**（考场级放宽同班相邻、按科目借考、非矩形加座考场）+ 两个体验性能力 + 一个真 bug。

---

## 1. 真实需求（这次要排的场）

- 名单：720 行，14 人「是否缺考=是」→ **参考 706 人**，18 个班（2501–2518）。
- 考务表给 19 个考场（考场名 + 考室地点）。**小教室只能放 5 列×7 排 = 35 座**（高一 1/2/3/4 班教室、高一十八班教室、一楼走班教室、录播教室）；其余大教室按 7 列×6 排 = 42 座。
- 19 间容量 = 12×42 + 7×35 = **749 ≥ 706**，够。

### 1.1 时段结构（老师给定的，也是 3+1+2 的必然结果）

| 时段         | 科目                 | 说明                                                               |
| ------------ | -------------------- | ------------------------------------------------------------------ |
| T1 / T2 / T3 | 语文 / 数学 / 外语   | 全员                                                               |
| T4           | **物理 + 历史**      | 首选科目，两门可以同时考（没人既选物理又选历史）                   |
| T5           | **化学**（单独一段） | 选化学的人最多，必须独占                                           |
| T6           | **生物 + 地理**      | 没有学生同时选生物和地理，可以同时考                               |
| T7           | **政治**（单独一段） | 选了政治的学生（物化政/史地政/史生政）与生物、地理都冲突，只能独占 |

> 名单完整时程序推出来的就是这张表（`out/intent2_plan.json` 的 `slots`）；一旦有人被 `included:false` 手工剔除，程序会把它推歪（见 §3.4）。

### 1.2 目标排法（已用"临时把第十七考场放大到 45 座"验证，只差两个放宽）

| 考场                   | 地点                                                               | 规格                              | 谁                                                            | 人数              |
| ---------------------- | ------------------------------------------------------------------ | --------------------------------- | ------------------------------------------------------------- | ----------------- |
| 第一～十六考场         | 高一·四/五/六/八/十/一/二/十一/十二/十三/十五/三/七/九/十四/十六班 | 12 间 7×6=42 + 4 间 7×5=35        | 物化生                                                        | **644，正好坐满** |
| **第十七考场**         | **高一·十八班**                                                    | **7×5=35**                        | 2518 全班 22 + 2517 的史地政 6 +（史生政某生的语数外史政）    | 29                |
| **第十八考场**         | **一楼走班教室**                                                   | **7×5=35**                        | 物化政 13 + 物化地 9 + 物化生溢出 11 = 33                     | 33                |
| —                      | —                                                                  | （小教室若按真实 37 座，见 §3.5） | 第一～十六考场 = 652 座 → 物化生只溢出 3 人，走班教室 = 25 人 | —                 |
| **第十九考场（政地）** | 录播教室                                                           | 7×5=35                            | **政治（物化政 13）/ 地理（物化地 9）** 专用考场              | 22                |

**某生（2517，史生政）的走位**（老师原话："他在考历史的时候在历史考场，考生物的时候专门跑到物化生的考场去考一下，或者跑到那个走班教室去考一下"）：

- T1–T4 + T7（语数外史政）→ **第十七考场**（跟史地政同场，同科不冲突）；
- **T6 生物 → 第十八考场（走班教室）借考**：该考场 T6 只有 11 名物化生考生物、另有 24 个空位，他坐一个空位考生物，**该考场该时段仍然只有"生物"一张卷子**；
- 绝不允许：让他在第十七考场（T6 考地理）里单独发生物卷子。

规则与约束（老师原话 → 结构化）：

1. **17 班（足球班 2517）必须靠墙**，且**只允许靠门内侧那面墙 = 第 1 列**（不是第 1 列或最后一列）。
2. **3 名作弊学生必须坐第一排**：2506 同学甲、2513 同学乙、2515 同学丙。
3. **选物理又选了政治/地理的学生（物化政 / 物化地）要有专门考场**：考政治/地理时去第十九考场（政地），平时（语数外物化）在主考场。
4. **2518（史地政）只能在一间小教室里"自己跟自己玩"**，同班挨着坐也接受（放宽同班相邻）；2517 的文科生也并进这间。
5. **走班教室要坐满**：物化政/物化地人少，就把物化生挤不下的塞进去。
6. 考场数量/名称/地点以考务表为准，尽量每个考场都用上、别空着。

## 3. 缺口清单

### 3.1 先说好消息：目标排法只差"两个放宽"

把第十七考场临时建模成 9×5=45 座（**只是为了绕过同班上限，不是为了放宽卷子规则**），其余完全按 §1.2 配置跑：

```bash
node packages/cli/bin/exam-seat.mjs plan --job out/job.probe.json --out-dir out/probe --json
```

结果（`out/probe_plan.json`）：**座位分布与 §1.2 目标表完全一致**

```
R1..R16  物化生 644 人（正好坐满）
R17      史地政 28 人（4 处同班相邻：2517 六人在第 1 列第 7/8/9 排挨着；2518 的 22 人之间也有）
R18      33 人（物化政 13 + 物化地 9 + 物化生 11）
R19      政治 14 人 / 地理 9 人          ← 注意：14 = 物化政 13 + 某生 1，程序把他的政治安排进了专用考场
```

剩下的问题只有两类：**第十七考场的同班相邻**（§3.2）和**某生的生物没地方考**（§3.3）。

---

### 3.2 【必备 1】考场级放宽「同班相邻」

**现象**：2518 的 22 人必须在第十七考场（35 座）里自己跟自己坐，必然出现同班相邻；程序直接判死。

**复现**：

```bash
node packages/cli/bin/exam-seat.mjs plan --job out/job.intent2.json --out-dir out/intent2
# [error] CLASS_LIMIT_EXCEEDED: 第十七考场：2518 有 22 人，但所有考场加起来最多只能容纳该班 18 人
```

**后果比"报错"更严重**：第十七考场这套座位方案**一个座位都没排出来**（`intent2_plan.json` 里 `seatings[R17].result.entries` 是空数组），`byStudent` 里这 28 人（2518 全班 + 2517 的 6 个史地政）**5 个时段全为空** —— 他们一个座位都没有。

**代码位置**：

- `packages/core/src/numbering.ts:60` `maxSameClass()`：`orthogonal` 下 = `ceil(rows*cols/2)`（35 座 → 18）；`king` 下 = `ceil(rows/2)*ceil(cols/2)`（更小）。
- `packages/core/src/precheck.ts:216-228` → `CLASS_LIMIT_EXCEEDED`（error）。
- `packages/core/src/plan.ts:82-88` `SOFTENABLE_CODES` **不含**它（`--relax` 救不了）；`plan.ts:109-124` `BLOCKING_EXPORT_CODES` **含**它（拒绝导出）。
- `packages/core/src/solver.ts:87-130`、`solver.ts:439-455`（自校验："X 号与 Y 号相邻，却都是 Z"）。

**期望**：允许**只对指定考场**放宽同班相邻；其余考场规则不变；结果照常导出并留痕。

**建议 API**：

```jsonc
// RoomSpec 新增
"relaxSameClass": true     // 完全放开
"relaxSameClass": 30       // 或自定义上限（本例 2518 有 22 人，给 30 足够）
```

**连带要求**：新增诊断码（如 `ROOM_SAME_CLASS_RELAXED`，warning）+ `PlanLevel` 增加放宽标记；不再进 `BLOCKING_EXPORT_CODES`；`validateAll()` 自校验要认识它；监考表表头标注"本考场已放宽同班相邻"。

**验收**：`plan --job out/job.intent2.json` 能导出，第十七考场 29 人、19 个考场全用上、`validate` 通过。

---

### 3.3 【必备 2】按科目借考（并入另一个已在用的考场，**不新增卷子规则例外**）

**现象**：某生（2517，史生政）T6 考生物，但第十七考场（他的主考场）T6 是地理 —— 按硬规则他不能待在那儿。老师给的合法做法是：**他 T6 走到第十八考场（走班教室，那时只有物化生在考生物、还有 24 个空位）借一个座位考生物**。程序现在没有这个能力。

**复现**：`out/job.intent2.json` 里 `C3b-史生政也在文科考场`（`studentIds:["33300001"], roomId:"R17"`）→

```
[error] RULE_INTERSECT_EMPTY: 第十七考场 已被别的批次占用（与已有批次逐时段冲突），
        被 roomId 限定到这里的学生（irregular-main）无法进入
```

而 `out/job.probe.json` 里他被排除后，`byStudent` 只有 T7 政治有位置（去了第十九考场），T1–T6 全空 —— 等于没学上。

**为什么会卡住（现有模型的两个隐含假设）**：

1. `SeatingPlan.subjects` 是**整套座位里所有学生科目的并集**（`plan-all.ts` 4a/4b），`findRoomSubjectClashes`（`plan-all.ts:118-154`）用"该并集 ∩ 时段科目"判断。只要把某生塞进第十七考场，并集里就有"生物"，而 T6 时段含地理 → 判成 `ROOM_SUBJECT_CLASH`。
   实际语义应该是：**这个座位方案在这个时段到底开考哪一科**（按时段判定），而不是整场的科目并集。
2. 专用考场（`dedicatedSubjects`）必须是**独立的房间**：`plan-all.ts:555-568` 把这种房间从 `generalRooms` 里摘掉，`:814` 的 4c 只往这些房间排。所以我们没法让"生物"的座位落在**已经在用的**走班教室里。

**期望**：

- 支持"某学生某科目到指定考场借考"：该时段占用目标考场的一个**空位**（不需要目标考场为此改变用途，也不需要第二张卷子）；
- 约束校验必须保证：**目标考场在该时段恰好只开考这一科**（否则报错，不静默混排）；
- `byStudent[student].slots[slot]` 指向目标考场 + 座位号，`distinctRooms` 计入（本例某生用 2 个考场，未超过 `maxRoomsPerStudent: 3`）；
- 监考表要体现"借考生"：该考场该时段多一个座位，标注"借考"。

**建议 API**（两种写法都行，推荐第一种，最贴近老师的话）：

```jsonc
// Student 新增：这个学生这几个科目去别的考场借考
{
  "id": "33300001",
  "name": "某生",
  "className": "2517",
  "combination": "史生政",
  "subjects": ["biology", "politics", "history"],
  "subjectRoom": { "biology": "R18" },
}
```

```jsonc
// 或者顶层新增"并考/借考"声明
"borrowSeats": [ { "studentIds": ["33300001"], "subject": "biology", "roomId": "R18" } ]
```

**实现上必须一并改的两处**：

1. `findRoomSubjectClashes` / `validateAll`：判定"一个考场一个时段一科"时，用**该考场该时段实际开考科目**（考虑借考生的时段，而不是座位科目的并集）。
2. 求解器：借考座位要在目标考场的座位方案里占一个该时段的空位，并与该时段该考场的其它考生座位不冲突（不同时段可以复用同一个座号）。

**验收**：某生出现在第十八考场的 T6 座位里（科目=生物），该考场 T6 的科目集合仍是 `{biology}`；他 T1–T4/T7 在第十七考场；`validate` 通过；不出现 `ROOM_SUBJECT_CLASH`。

### 3.4 【强烈建议】时段表可显式指定 + 剔除学生后时段不能变形

**现象**：为了手工编排把文科生（史地政/史生政）从 job 里剔除后，**时段划分跟着变了**：生物/政治/地理 被并进同一时段 T6（它们之间的"冲突边"来自被剔除的组合），于是第十九考场（政治+地理专用）被判 `ROOM_SUBJECT_CLASH`，拒绝导出：

```bash
node packages/cli/bin/exam-seat.mjs plan --job out/job.tool.json --out-dir out/tool
# [error] ROOM_SUBJECT_CLASH: 第十九考场 （政地） 在第6时段同时安排了 地理、政治：一个考场一个时段只能考一科
# out/tool_plan.json 的 slots：T6 = [biology, politics, geography]
```

**代码位置**：`schedule.ts:72` `deriveTimeSlots()`（+ `buildConflictGraph` at `:32`），只吃 `compileModel` 里**参考学生**的组合（`plan-all.ts:543-552`）。

**期望**（建议都要）：

1. `options.slots` 直接给定时段表（老师按考务表填死，§1.1 那张表）；
2. 或 `options.forbiddenSameSlot: [["chemistry","biology"],["chemistry","geography"],["chemistry","politics"],["chemistry","history"],…]` 只补"必须分开"的科目对；
3. 或学生支持 `planningOnly: true`（参与时段推导/容量统计，但不自动排座，给人工作业留位）。

**顺带一个真 bug**：`splitByRequiredRoom`（`plan-all.ts:280`）把"整批钉考场"的批次拆成"钉住的 + 未钉住的"两段，而 `allocateDemands` 的 `cursor`（`plan-all.ts:461-490`）只前进不回头 → 未钉住的那 6 人扫到 rooms 末尾直接算缺座：

```bash
node packages/cli/bin/exam-seat.mjs plan --job out/job.intent.json --out-dir out/intent
# [error] CAPACITY_INSUFFICIENT: 普通考场不够：还缺 7 个座位
```

（7 = 史地政未钉住的 6 人 + 史生政 1 人，而实际第十七考场还空着。）**期望**：未钉住的部分能回到本批次已占用的考场，或每个批次各自维护游标。

---

### 3.5 【必备 3】非矩形考场：5 列×7 排 + 讲台两侧 2 个加座 = 37 座

真实教室：5 列×7 排 = 35，再在**讲台一侧**第 2、4 列各加 1 张桌 = **37 座**（"不能再多"）。现在 `RoomSpec` 只有 `rows/cols`（矩形），37 表达不出来，而且编号会错。

**编号规则已经写进 `docs/design.md` §4.5**（含 37 座示意图、逐句对账、《建议字段与实现要点》），要点：

- 每列座位数不再相同：`n = [7, 8, 7, 8, 7]`；
- 沿用按列蛇形：第 1 列（靠门）1–7；第 2 列 8（最后一排）→14（第一排）→**加座 15**；第 3 列 16–22；第 4 列 23→29→**加座 30**；第 5 列 31–37；
- 加座在讲台一侧（`r1` 之前），邻接、`maxSameClass`、座位缩略图都要跟着改，别按矩形算。

**用了 37 座之后的目标人数**（12×42 + 4×37 = 652）：物化生 655 → **3 人溢出到走班教室**（走班教室 = 物化政 13 + 物化地 9 + 物化生 3 = 25 人）。

## 4. 建议的 schema 草案（汇总）

```jsonc
{
  "options": {
    "slots": [
      { "id": "T1", "name": "第1时段", "subjects": ["chinese"] },
      { "id": "T4", "name": "第4时段", "subjects": ["physics", "history"] },
      { "id": "T6", "name": "第6时段", "subjects": ["biology", "geography"] },
      // …
    ],
  },
  "students": [
    {
      "id": "33300001",
      "name": "某生",
      "className": "2517",
      "combination": "史生政",
      "subjects": ["biology", "politics", "history"],
      "subjectRoom": { "biology": "R18" },
    }, // ← 必备 2：T6 去走班教室借考
  ],
  "rooms": [
    {
      "id": "R17",
      "name": "第十七考场",
      "location": "高一·十八班",
      "rows": 7,
      "cols": 5,
      "relaxSameClass": true, // ← 必备 1
      "assignedCombinations": ["史地政"],
    }, // 可选：声明用途，比 roomId 钉人直观
  ],
}
```

**设计原则（老师原话的精神）**：个别地点加限制、个别地点放宽，都是**考场级/学生级的开关**，互不影响；每一次放宽都要在 `plan.json` 留一条 diagnostic，并在监考表上标注。
**不变的红线**：一个考场、一个时段、只能有一张卷子（借考只是"换座位"，不是"加卷子"）。

## 7. 附：已确认"能用、别改坏"的能力

- `RoomSpec.rows/cols` 逐考场规格；`name` / `location` / `note` 照原样进表头。
- `RoomSpec.dedicatedSubjects`：一个专用考场可兼多科（政治 T7 + 地理 T6，不同时段即可）。
- `options.groupPreference: "fillRooms"`：不同批次共用考场（实测把物化生溢出塞进走班教室，报 `ROOMS_SHARED` warning）。
- `constraints`：`studentIds`/`classes`/`combinations`/`subjects` 选择器取并集，`roomId` 单选，`rows:["first","last",n]`、`cols:["door","window",n]`；`cols:["door"]` 就是"靠门第 1 列"。
- 班数 < 9 的考场自动退化为 4 邻域（`precheck.ts:36`），第十七～十九考场正是靠这个才可能排下。
- 多场次两份交付物 + `plan.json` / `job.json` / `validate`。
- `byStudent[].slots` 天然是"逐时段 → 考场 + 座位"，借考功能可以直接落在这一层。
